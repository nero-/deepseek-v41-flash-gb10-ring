# Clean upstream SparkRing comparison — October 14, 2026 (HST)

Decision: retain the original corrected build. The clean upstream image/profile
passed the finite qualification checks but did not improve the requested C8/C16
workloads. Original restoration and final validation passed; see `final-audit.json`.
The API is healthy on port 8015, only the four original containers are running,
and the enabled 2350 MHz clock-cap services and legacy mesh are active.

## What corrected the apparent performance gap

Both builds were measured with an unmodified LIL 0.7.6 script at
`bbfec004beac908692030b10b14846db4a3c6457`, using the published ring-of-four
invocation: concurrency 1,2,4,8,16; contexts 8K,16K,32K,64K,128K; temperature 1;
20-second sustained cells; max output 2048; integrated prefill scouts; five coding
probes. Both local runs used gx10-r0 as the client and retained the 0–2350 MHz
GPU policy. The published upstream run used an external workstation and GPUs
locked at 2418 MHz.

Our historical `lil_matched.py` adapter forces thinking=false, top_p=1 and
top_k=-1, as well as temperature=1. The published invocation leaves thinking,
top_p and top_k at server/model defaults. The LIL `run_one_cell` function's source
is identical between the retained 0.6.2 and this 0.7.6. The higher original-build
numbers below reflect a different request contract, **not an engine upgrade**.
Historical thinking-off measurements remain valid for that workload.

## Qualification and scope

- Seven functional checks passed, including tools, forced tools, vision and thinking.
- Twelve exact-answer checks passed.
- Two fixed 2048-token teacher-forced comparisons showed no obvious distribution
  regression. Coarsened top-20 KL versus the original was 0.00677/0.01261, with
  top-1 agreement 98.63%/96.68%. This finite screen does not establish broad quality equivalence.
- Uncached 125,238-token retrieval passed; cached_tokens=0, TTFT 34.24 seconds.
- SIRCL ready/traffic receipts verified on all four ranks; NCCL none, PyNccl skipped.
- Startup GPU samples were 2320–2333 MHz, consistent with the preserved ceiling.

The first staging attempt omitted follower `--headless` flags. All trial workers
were stopped, command construction switched to upstream's own generator, and the
failed attempt archived. No serving benchmark used that attempt. Corrected startup
took 302 seconds.

The trial changes the image, transport and local-plugin selection together; it
does not isolate SIRCL's effect. Samples are short and stochastic, with no confidence
intervals. Published and local clocks/client locations differ. The existing
original selection, per-rank images, plugin bundle and checkpoint were preserved.

With matched upstream requests, our existing recipe already measures about
193–198 tokens/s at C8 and 264–271 at C16. Reaching 300 at C16 requires roughly
11–14% more throughput on these contexts, rather than the earlier estimate based
on unlike request settings. Keep the clean copy as a comparison baseline; no
performance gain justifies promoting it as the default from this run.
